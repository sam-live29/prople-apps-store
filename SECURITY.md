# Security Policy

## Reporting a Vulnerability

The Prople Store team and **Cloaktail Industries** take the security of our platform, developers, and users seriously. We appreciate the responsible disclosure of security vulnerabilities by independent security researchers and community contributors.

### Supported Versions

Only the latest active release branch is currently supported with security updates.

| Version | Supported          |
| ------- | ------------------ |
| Main (Latest) | :white_check_mark: |
| < 1.0.0 | :x:                |

---

### How to Report

**Please do NOT report security vulnerabilities via public GitHub issues, discussions, or pull requests.**

Instead, please report vulnerabilities directly to our security response team through either of the following channels:

- **Email**: [cloaktailsupport@gmail.com](mailto:cloaktailsupport@gmail.com)
- **Alternate Contact**: [cloaktailofficial@gmail.com](mailto:cloaktailofficial@gmail.com)
- **RFC 9116 Metadata**: [https://www.prople.co.in/.well-known/security.txt](https://www.prople.co.in/.well-known/security.txt)

Please include the following information in your advisory:

1. **Description**: Clear summary of the issue, vulnerability classification (e.g., SSRF, XSS, IDOR, Auth bypass, Token leakage).
2. **Steps to Reproduce**: A minimal, reproducible proof of concept (PoC) or step-by-step instructions.
3. **Potential Impact**: Who or what is affected (e.g., user account takeover, data leak, denial of service).
4. **Suggested Mitigation**: If you have identified a fix or architectural defense, please provide your recommendations.

---

### Our Response Timeline

- **Initial Acknowledgment**: Within 24-48 hours of receipt.
- **Triage & Assessment**: Within 3-5 business days.
- **Remediation & Patching**: High and critical issues are addressed and deployed with immediate priority.
- **Credit & Disclosure**: Once a patch is confirmed and deployed, we will coordinate public disclosure and provide acknowledgment in our release notes and security page.

---

### Safe Harbor

We will not pursue civil or criminal action against researchers who:
- Perform testing within the scope of security research without exploiting data or disrupting services.
- Refrain from accessing, modifying, or destroying user data without authorization.
- Provide us a reasonable amount of time to remediate vulnerabilities prior to public disclosure.
- Act in good faith and comply with applicable laws.
